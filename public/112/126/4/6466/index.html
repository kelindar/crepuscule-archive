se quote

La première ligne dit mobile.Acrobatie ça désigne uniquement la Compétence ACROBATIE that's it. Ce qui suit désigne les skills et le nombre a la fin est l'incrémantation du totalcap (+1/+2) Une ligne vide signifie le début de l'autre compétence.

Exemple :

mobile.**Alchimie **++; (COMPÉTENCE) mobile.Skills[SkillName.Alchemy].Cap += 2.0; mobile.Skills[SkillName.Poisoning].Cap += 1.0; (SKILL += Le nombre qu'il augmente par point dans cette compétence)

Voila c'est tout simple la.

Précision :

Les compétences qui donneraient +3 dans un skills seraient des skills moins utilisés afin de favoriser une diversification des joueurs.

Exemple :

-Concentration de guerre (focus)
-Begging
-Herding
-Fishing
-Tracking

Post by Arvendor Vasyr, AdC - May 22, 2006 at 4:18 AM

Voila j'ai tout terminé. Voici les informations :

Il n'y a pas de limite dans les compétences , toutefois il y a un skillcap total de 100. Ainsi, quelqu'un avec 700 en couture n'aura jamais plus de 100 de tailoring. Je l'ai mit sous forme de constante dans le code donc ce ne sera pas difficile à modifier si jamais le shard devient hyper haut lvl machin truc.

Vous pouvez mettre des compétences négatives. Les skillscaps descendront alors pour une limite de 20. Ça peut être utile pour des objets maudits, ect.

Vous pouvez désormais modifier le .props des joueurs et les skillscaps se modifiront automatiquement. Le .fiche, lors du clique sur une compétence, va modifier le truc dans le .props qui lui modifie le skillcap.

Ainsi, vous pouvez librement débugger les joueurs et jouer dans leurs compétences sans risquer de bugger les perso à tout jamais comme avant.
