Post by Coordinateur Apoc - September 13, 2012 at 11:50 PM

C'est qu'une hypothèse mais je dirais que: Un objet décay quand il est au sol un certains lapse de temps sans être déplacé et les saves effaces les objets si leur compteur de decay est à 0. Le .verrou met le decay à false et le remet à true ensuite. Mais le compteur lui continue peut-être de compter même si le decay est à false. Donc en enlevant le verrou le decay est tombé à true au moment du save.

Étrange par contre que d'ajouter quelque chose dans un stack ne remet pas le compteur à zéro. Le decay est pas mal profond dans la base de UO donc c'est pas un bonne idée de trop jouer avec ca.

Il faudrait faire des tests mais voir si essayer de déplacer un objet .verrou remet le compteur à zéro même si l'objet ne peut pas bouger, ca pourrait être une bonne solution qui ne demande pas de jouer dans les scripts. Sinon, les saves sont annoncés un peu avant d'arriver donc faire attention de ne pas rien déverrouiller à ce moment.

Pour ce qui est de remettre les objets... C'est malheureusement quelque chose qu'on ne peut pas faire vu qu'on ne peut pas prouver ce qui est arrivé.
